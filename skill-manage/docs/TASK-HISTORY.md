# T05：任务历史分页与检索

开发版本 0.3.2.dev6，SQLite schema 4。任务中心支持关键词、Skill、状态、审计/修复类型和每页 25/50/100 条筛选，可前后翻页、清空条件、刷新最新。关键词按字面匹配 Skill 名称/slug、版本或任务 ID，百分号和下划线不会作为通配符。

## 接口与顺序

| 接口 | 参数 | 权限 |
| --- | --- | --- |
| `GET /api/task-history` | `limit`、`cursor`、`q`、`state`、`skill_id`、`kind` | 已登录用户，共享只读 |
| `GET /api/tasks/{id}/events` | `limit`、`cursor` | 已登录用户，匹配该任务/审计/修复的事件 |
| `GET /api/worker-enrollment-history` | `limit`、`cursor` | 仅管理员；不返回接入码或其 hash |

返回 `{items, hasMore, nextCursor}`。limit 范围 1–100；任务默认 25，事件默认 50，接入记录默认 25。旧 `/tasks`、任务详情中的 `events` 和 `/worker-enrollments` 保留原响应形状，工作台使用新接口遍历历史。

任务和接入记录按 SQLite 登记顺序倒序，事件按事件 ID 正序。首个请求固定当时最大登记序号，后续游标固定该上界并从最后一个序号继续；相同时间戳不会造成重复，后来插入的记录不会挤入历史页。游标绑定用户、接口范围、任务和筛选条件；改变条件或换账号须重新开始。所有 SQL 值参数化，不使用 OFFSET。

这是记录范围快照，不冻结任务状态或撤销状态；筛选仍反映读取当时的状态。刷新重新开始并包含新记录。任务读权限仍为团队共享，取消任务、发布与修改权限不变；普通成员不能操作他人任务或读取接入记录。

## 工作台行为

任务首页继续轮询，但输入筛选时不重画表单，历史页不自动跳回首页。换页返回列表顶部，返回上一页恢复原游标。手机上筛选逐行排列，任务表格在容器内横向滚动。

审计和修复详情都提供事件连续加载。已展开的事件页保存在当前页面状态中，详情轮询不清空；刷新事件重新取最新范围。任务详情额外返回 `latest_model_error`，独立查询最近的稳定模型错误，即使错误位于旧版 200 条上限之后也能显示。只展示已有稳定码和统计，不记录原始模型上下文或密钥。

设置页的接入码记录以 25 条起始，可加载更早记录；操作后的刷新重新取最新范围。退出登录会清空历史游标和缓存。

## 验证

本地完整 179 项测试通过。新增检查用真实 SQLite/API 遍历 235 条同时间戳任务、超过 200 条事件及 120 条接入记录，验证插入快照、无重复/遗漏、关键词转义、用户/筛选/任务游标边界、管理员权限和取消权限。真实修复 fixture 另验证修复状态能正确关联到筛选结果。

浏览器验证使用隔离本地实例和专用合成历史记录，不配置模型，不把种子任务当作真实模型审计。实际筛选、前后翻页、输入轮询保护及 1440/390 像素布局单独验证；该实例与现有用户数据分离。
