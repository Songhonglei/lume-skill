## 1. 固定边界与交付物

- 自托管，个人/小团队共享 Skill 库；管理员与单一 Skill 维护者两类权限。
- 仅 SQLite + 本地文件，PG/MySQL 等后续评估。
- Docker Compose 与不依赖 Docker 的 CLI 原生路径均须完成端到端验收。
- 上传 ZIP/目录或公开下载 URL；未来接自定义 SkillHub。
- 独立 worker，一次性码接入，模型设置默认由平台统一管理。
- 注册 → 审计 → 授权修复 → 独立复审 → 本平台新版本 → 下载完整闭环。
- 不包含评测、企业 SSO、多租户、任意代码执行或内部平台兼容。

交付物：本地干净 Git 仓库、Python wheel/源码包、Compose/Dockerfile、CLI、Web、独立 worker、内置增强通用 Skill、合成示例、测试、安装/运维/备份恢复文档。远端公开发布另按授权处理。

## 3. P0：基线与契约

- P0-01：初始化当前目录的干净 Git 仓库；列出可提取、需重写、禁止带入三类文件，记录来源与许可证。原项目只读，不带旧 Git 历史。
- P0-02：冻结数据对象：users、skills、versions、artifacts、audit_runs、findings、repair_runs、tasks、task_attempts、worker_enrollments、workers、events；明确唯一约束和所有权。
- P0-03：定义任务、审计、交付、修复四种状态，避免一个 status 混用。定义输入 manifest、结果 JSON、报告指纹、租约和版本登记契约。
- P0-04：冻结 CLI 与 Web 初始化共用配置，模型能力检查和受约束 Agent 工具协议；明确原生执行不运行目标代码。
- P0-05：登记 deep-audit 上游 commit、财务候选基线、A1–A9 迁移清单及合成样例。

验收：每条用户需求都有对应阶段和验收编号；包身份、授权、任务恢复和两种安装模式无未决架构矛盾。不把原项目尚未验证的自动同步结论当成本项目证据。

## 4. P1：两种安装方式与存储骨架

- P1-01：建立 Python 包、console entry point、FastAPI、打包静态资源与内置 Skill，固定依赖和发行物版本。
- P1-02：实现 SQLite 初始化/编号迁移、WAL、外键、短事务、busy timeout 与数据目录约定；无 PG 专用 SQL。
- P1-03：实现 CLI setup 和 Web onboard 共用服务；一次性初始化凭据、管理员创建、配置验证、模型检测，重复执行幂等。
- P1-04：实现 Compose 服务、持久卷、健康检查、启动顺序、自动内置 worker 配对；镜像运行不要求下载内部资源。
- P1-05：实现原生 CLI 安装、启动/停止/状态/日志/诊断；使用锁和进程身份核验避免重复拉起或误杀无关进程，正确处理子进程退出。
- P1-06：形成备份/恢复接口骨架，数据目录和配置中敏感值不进入 Git 或诊断输出。

验收：Linux 上两种模式首次启动与重复 setup 均通过；macOS 原生可启动。CLI 原生完整启动不要求 Docker。依赖缺失、端口冲突、目录不可写、SQLite 迁移失败有可操作提示，不静默创建第二套数据。

## 5. P2：Skill 注册、版本和用户权限

- P2-01：本地账号/会话、管理员管理用户、维护者归属检查；首期共享只读库，写操作按 Skill 所有权。
- P2-02：ZIP、目录上传和公开包 URL 获取，自动解析 SKILL.md，名称/版本缺失时最少补填。
- P2-03：安全解包、URL/重定向目标限制、大小/数量限制、原包/内容摘要及去重。
- P2-04：不可变版本登记、文件浏览、包下载、当前可用版本指针；同版本异内容不覆盖。
- P2-05：通用 Skill 列表与详情页；清除财务词汇、内部链接、埋点、评测菜单和旧发布组件。

验收：上传→详情→下载摘要一致；同包重复导入不重复建版本；维护者越权被 API 拒绝；非法 ZIP、错误 URL 和路径越界均有实际反例测试。

## 6. P3：独立 worker 与一次性授权码

- P3-01：任务创建、原子领取、租约/心跳、attempt、停止、超时、退避和重试；默认执行并发 1。
- P3-02：API 提供固定包下载、日志事件、产物提交；worker 不访问 SQLite，不需共享服务器目录。
- P3-03：管理员生成 10 分钟一次性码，隐藏输入兑换、事务消费、worker 专用凭据本地持久保存、吊销和状态回显。
- P3-04：处理兑换回执丢失与未上线登记；不复用已消费码，重接入可撤销旧登记。机器凭据不等于管理员会话。
- P3-05：实现内置与外接 worker 统一 runner、关闭浏览器持续运行、重启恢复；迟到结果由租约代次拒绝。
- P3-06：平台模型配置通过受任务范围约束的模型调用 API 使用，外接 worker 不需再填写模型 Key；不是任意 URL 代理。模型调用配额、任务类型和请求上下文受平台限制。
- P3-07：固定工具的路径边界、超时/取消、输出大小和日志脱敏。外接 worker 是管理员认可的执行机器，会处理所分配 Skill 内容，首期不设计不可信第三方算力市场。

验收：一台独立本机以平台地址+一次性码加入，真实领任务并提交；过期/撤销/重复/并发兑换正确；worker 离线、进程终止、响应丢失、重复提交、停止后迟到结果都有回归。撤销机器凭据后不能继续提交有效结果或访问模型代理。

## 7. P4：增强通用审计

- P4-01：白名单导入 skill-deep-audit 及许可证/来源，保留独立交互模式；实现机器输入契约，任务已声明深度时不再次等待聊天。
- P4-02：实施能力清单 A1/A2/A6/A7/A9，核对检查器源码与行为差分，不以版本号推断所有变化都能直接合并。
- P4-03：实施结构化 findings、repairPrompt、规则版本、manifest、report digest；统一 JSON schema、分数与零分 ERR 校验。
- P4-04：实现静态检查＋内置 Agent 语义审计，缺工具/模型/可选 Hub 分别处理；必需结论未决时显示待复核。
- P4-05：报告原文和台账在 SQLite 同一事务保存；同 run 重传幂等，错误报告拒收，保存失败保留本地冻结产物。
- P4-06：审计报告、问题列表、交付状态和修复入口 UI；合成正反例覆盖版本错配、检查失败、0 分 ERR 和误报。

验收：一个合成通过样例和一个失败样例均真实执行；查回报告、JSON、分数及包身份一致。模拟测试验证协议边界，真实模型测试验证语义执行，二者分开留证。独立 Skill 不装平台也能生成报告。

## 8. P5：自动修复完整闭环

- P5-01：问题选择和一次授权快照，ERR 默认选中；修复 Prompt 以所选 ID 为范围，不能把未选问题暗中加入。
- P5-02：不可变原包＋候选副本，Agent 受限文件修改，生成逐文件差异；版本号调整在复审前完成。
- P5-03：固定语法/边界检查和新会话全量复审；不运行被审 Skill 业务脚本和不受控测试。
- P5-04：最多 3 轮反馈修复；遇到无法判断的行为变更、越界、预算耗尽或模型失败进入待处理，不无限循环。
- P5-05：最终 Gate 校验选定规则、完整审计、交付成功、候选摘要、授权和执行终态；幂等登记新版本，保留原版本。
- P5-06：任务中心展示阶段、日志、轮次、差异与剩余问题；取消、仅候选模式、当前版本切换均有明确回执。

验收：真实模型修复一个含脚本/文档缺陷的合成 Skill，独立复审通过后下载新包；另验修复仍失败、复审后篡改、3 轮未收敛、用户取消、重复发布提交、修复期间原 Skill 出现新版本的冲突。不得以预置结果或只改一个固定字符串的测试替代真实闭环。

## 9. P6：发行与完整验收

- P6-01：全新 Linux 环境分别用 Compose 与 wheel/CLI 安装；macOS 原生执行主链路，记录未覆盖平台。
- P6-02：两条路径完成注册→审计→修复→复审→新版本下载；验证后台持久运行和外接 worker。
- P6-03：实现一致性备份/恢复，恢复到空目录后校验元数据、报告与包摘要；升级前备份，迁移失败停止，恢复旧包+备份作为回退方案。
- P6-04：核查浏览器资源、安装源和运行请求无内部依赖；包中无业务样例、旧日志、人员信息或凭据。
- P6-05：维护 quickstart、CLI 命令、worker 接入、默认值、模型限制、备份恢复和问题排查文档；所有安装说明由干净环境验证。
- P6-06：配套 Skill 按 UGLIC → skill-release-audit → 修复与复核执行；平台做相称的端到端、权限、包处理、租约及依赖检查。误报保留依据，不为消警破坏正确行为。
- P6-07：本地 Git 整理可审阅提交和发行说明；未授权前不创建公开远端、不推送、不发布包或镜像。

验收：交付安装包和演示路径、检查证据、已知限制及恢复说明。所有必需检查完成，范围内不存在用“后续再补”替代自动修复、CLI 或 worker 接入的缺口。

## 10. 拟定 CLI 契约

下表保留首期命令目标。当前可用项和 worker 限制见 README 与 CLI --help；`skill-mng` 已作为本地入口实现。安装支持本地 wheel/源码，尚未发布公共包名。

| 命令 | 用途 |
| --- | --- |
| `skill-mng setup` | 交互初始化账号、模型、数据目录；已有安装只补缺失项 |
| `skill-mng start` / `stop` / `status` / `logs` | 默认管理当前安装的 Web 与内置 worker |
| `skill-mng server start` | 单独启动 Web/API |
| `skill-mng worker join --server <URL>` | 隐藏输入一次性授权码，保存机器凭据；自动化可用 stdin 输入 |
| `skill-mng worker start` / `stop` / `status` | 独立 worker 生命周期 |
| `skill-mng config` | 查看脱敏配置或进入设置；不打印密钥 |
| `skill-mng doctor` | 检查版本、路径、SQLite、端口、连接、worker 与模型能力 |
| `skill-mng backup` / `restore` | 一致性备份、校验和停写恢复；覆盖前明确提示 |
| `skill-mng db migrate` | 对当前安装执行编号迁移；不支持隐式降级 |

模型设置不是 Agent CLI 依赖。CLI 安装/管理是本期功能，多品牌 Agent CLI 执行器仍不在首期范围。

CLI 与 Compose 数据路径不同也必须采用同一数据格式；通过官方备份/恢复迁移，不让两个 Web 实例同时打开同一数据目录。升级流程为备份→安装固定版本包/镜像→迁移→健康核验，保留旧包版本和恢复入口。
