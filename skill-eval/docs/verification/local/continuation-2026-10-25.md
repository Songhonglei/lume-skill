日期：2026-10-25（Asia/Shanghai）。起点为公开 main `eca5e692c142d0305d4dd5ef1029874720715d7e`；以下针对该基线上的本地编辑器修复，不声称已合入 main 或通过远端 CI。

## 本次修复

1. 案例 `judge.success` 含 `null` 时，源码编辑会触发 React 渲染异常，整个工作台白屏。现先检查 YAML 是否可安全映射到表单，异常结构提示用源码修复；原内容保持可编辑、可存草稿，启用仍由中心全量校验把关。复杂和未知字段不通过删减来修复。
2. 浏览器 `TextDecoder` 默认移除 UTF-8 BOM，附件未经编辑就改变了原始字节。现保留 BOM，NUL 或无效 UTF-8 按 base64 保存。单元测试覆盖中文、CRLF、空文件与较大二进制文件。
3. 保存请求期间仍可编辑或切换版本，可能在响应到达时丢掉后续修改。现读取附件、保存、校验与保存版本期间锁定编辑区、Skill/评测集/版本切换及导入、生成入口，完成或失败后恢复。
4. 保存成功时，旧的版本读取快照可能暂时把界面恢复到保存前的内容。现按 `edit_number` 拒绝旧快照，已归档的草稿也不会被旧快照恢复为可编辑。
5. 上传同名附件原先直接覆盖。现显示页面内确认，取消保留全部原附件，确认后才读取并替换所选附件。

新增 `npm --prefix frontend test`，直接使用 Node 内置测试运行器和 TypeScript 类型剥离，不增加运行时或测试依赖；GitHub 检查工作流已接入该步骤。

## 浏览器收据

使用 ego-browser，实际 FastAPI → PostgreSQL → 文件库，未用模拟接口替代保存/启用。为复现竞态，仅临时延迟浏览器 fetch，请求仍交给真实 API，验证后恢复 fetch。

| 场景 | 观察 |
| --- | --- |
| 异常 YAML | 修复前 `success: [null]` 可复现白屏；修复后表单提示源码编辑，切回源码仍保留该内容 |
| 慢速保存 | PUT 未完成时，源码、版本、Skill 和导入按钮均锁定；完成后解锁 |
| 保存后的延迟读取 | 挂起保存后的 GET，界面仍保留刚保存的 newest.txt 和内容，不回退旧文件列表 |
| BOM 与换行 | 上传后保存草稿，再从 API 读取，BOM 与 CRLF 保持 |
| 重复附件 | 页面列出 bom.txt；取消仍为 Original；确认后变为 Replacement |
| 二进制附件 | 可上传与预览占位，保存后导出保留全部 256 种字节 |
| 保存并启用 | 选中新的已启用版本，表单只读，显示“创建草稿后编辑” |
| ZIP 导出 | 已保存版本导出 8 个文件，BOM/CRLF、binary.bin、newest.txt 和原判分脚本逐字节核对通过 |
| 900px 视口 | 页面宽度 900px，无横向溢出；截图检查通过 |

本机原始截图和导出包位于忽略目录 `.local/browser-evidence/`，合成附件位于 `.local/browser-fixtures/`。会话和本机开发管理员资料不进入公开证据。文件哈希及脱敏检查摘要见 [continuation-2026-10-25.json](continuation-2026-10-25.json)。
