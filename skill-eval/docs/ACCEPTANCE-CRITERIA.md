# 验收标准

日期：2026-10-23。状态：验收定义，**所有项目尚未执行**。

关联：[完整方案](PRODUCT-AND-TECHNICAL-PLAN.md)、[开发计划](DEVELOPMENT-PLAN.md)。

## 1. 验收原则

一期可交付必须同时满足：无企业平台依赖、原生 0.14.0 + Codex 真实执行、案例可维护且优先复用、独立 Worker 单码接入、标准评测全部案例、全新环境可部署。

验收环境使用隔离数据库和合成数据；真实模型调用只使用明确配置的测试连接。任何历史内部验收结果、模拟 Worker 回执或手写 result.json 都不能替代本项目真实 E2E。

结果枚举为 PASS、FAIL、BLOCKED、N/A；未执行标记 NOT_RUN。必须记录环境和版本、前置条件、步骤、预期/实际结果及脱敏证据。必需项不能用 N/A 绕过。

## 2. 验收矩阵

以下 AC-01 至 AC-32 均为一期必需项。每项包含的子条件全部满足才能通过。

| ID | 场景与步骤 | 通过标准 |
| --- | --- | --- |
| AC-01 | 新目录检出代码，审查文件来源及 Git 历史 | 不含原工作区历史、业务数据、凭据、个人路径和部署包；所有迁入文件可追溯；仅用公开依赖即可构建 |
| AC-02 | 启动时阻断被移除的企业服务域名，走核心路径 | 上传、生成、评测、报告均无内部服务请求；未配置企业账号也可使用；生产配置无内部默认地址 |
| AC-03 | 检查 skill-up、Codex 和模型配置，运行真实最小案例 | 实际执行 skill-up 0.14.0，Codex 精确版本在兼容矩阵中；无静默升级/降级/改模型；报告记录请求配置和可核实实际信息 |
| AC-04 | 对同一用例分别制造断言失败、程序错误、跳过和缺报告 | 状态与结论按定义区分；CLI 非零退出不被简单等同为一种业务结论；空结果/跳过不会显示全部通过；保留原始数据 |
| AC-05 | 上传 ZIP 和目录形式 Skill，再重复上传并上传同名不同内容 | 识别根与 SKILL.md；相同内容去重；更新形成新版本；不同 Skill 不被名称误合并；上传不执行脚本 |
| AC-06 | 为 Skill 配置已启用案例，连续两次发起评测 | 默认选用该集；没有生成确认和生成调用；两次使用同一冻结案例版本；无模型生成成本 |
| AC-07 | Skill 无案例，取消提示；再确认生成；另测只有草稿场景 | 取消不建生成任务；确认才调用；草稿场景引导处理已有草稿，不错误判为无案例；提示也可选择上传 |
| AC-08 | Codex 自动生成案例并校验，再使用带预设缺陷的 Skill 变体运行 | 生成持久化到对应 Skill 的草稿；内容可理解、可编辑；正常变体满足核心断言，至少一个预设缺陷被识别；生成过程不修改 Skill、不自动评测 |
| AC-09 | 修改任务描述、断言、脚本、附件，增删案例，保存启用后重启 | 内容及附件保持；新版本被下一次评测使用；旧版本原字节不变；高级字段不被表单丢失；并发编辑冲突有提示 |
| AC-10 | 上传原生案例包和 evals.json；导出后重新导入 | 原生布局可被 0.14.0 validate 读取；转换前后语义有证据，转换结果可预览；导入导出无配置/凭据泄漏；非业务元数据可变化，案例内容语义保持 |
| AC-11 | 输入空集、无效 YAML、缺附件、未引用案例、多裁判和非 Codex 配置 | 明确列出问题；可保存草稿但不能误启用/执行；不删配置后静默运行；有效、非空集才能启用 |
| AC-12 | 新 Skill 版本复用旧案例；运行过程中编辑/启用新案例版本 | 旧案例可复用并显示来源版本；不自动重建；正在运行任务使用原快照；新任务使用新启用版本；旧报告仍能下载原引用 |
| AC-13 | 两类任务从网页发起，重复点击或模拟创建响应丢失 | 同幂等键同请求只产生一个任务，可查回；同键不同内容冲突；生成和评测类型清晰；无第二套独立生成调度系统 |
| AC-14 | 创建包含多种案例的评测集，点击标准评测 | 页面无模式/范围选择器；入口全部案例进入冻结清单；不抽样、不按名筛选；每个案例有结果或明确未完成原因；整体通过要求全部有效 PASS |
| AC-15 | 分别执行 rule_based、script、agent_judge 三种单裁判案例 | 三种路径均真实可用；expect 先决条件正确；语义裁判使用独立 Codex 会话；报告有每个案例判分方式；不存在多裁判累积评分 |
| AC-16 | 检查生成、被测与裁判各自工作区及注入内容 | 被测会话没有中心/Worker 凭据、其他 Skill 内容及裁判答案文件；不安装生成助手；生成只写案例目录；源 Skill 摘要不变；不得声明超出实际机制的绝对隔离 |
| AC-17 | 新机器安装 Worker，输入一个授权码；重启并撤销 | 无需分别填写 URL、Token、项目、Worker ID；自动注册和重连；重复兑换/过期码拒绝；撤销后不能领取或回传；无效模型登录给出单独清楚提示 |
| AC-18 | 同时启动两个 Worker 竞争同一任务，检查基础能力匹配 | 同一 attempt 只有一个有效领取者；不匹配版本/引擎的 Worker 不执行；无需小队或智能调度配置；等待原因可见 |
| AC-19 | 运行中短暂断网，再超过租约时长断网，随后恢复 | 短暂断网可续传且不重跑；过期后停止原进程并标中断；不自动派新执行；迟到结果不覆盖终态；人工重试产生新 attempt |
| AC-20 | 取消排队/运行任务，并制造成功与取消并发 | 排队取消不执行；运行取消结束任务进程组，无孤儿进程；中心收到确认后显示取消；终态唯一且不反复覆盖 |
| AC-21 | 篡改输入摘要、使用其他 attempt 提交、重复上传已接受结果 | 篡改/越权/过期租约拒绝；合法重复提交幂等；完整结果与冻结案例清单一致后才形成有效终态 |
| AC-22 | 上传路径穿越、符号链接、冲突路径、超限压缩包和含脚本 HTML | 拒绝不安全文件，不写任务/库目录外；限制解压大小和文件数；不自动执行；报告展示不获得中心同源脚本权限 |
| AC-23 | 检查日志、任务包、导出、Worker 子进程环境及磁盘权限 | 不含管理员/Worker/模型密钥；Worker 凭据权限受限，中心存摘要；模型凭据按方案受保护；只传当前任务必需变量，不挂整个 HOME/中心库 |
| AC-24 | 无效模型配置、模型不可用、超时、无输出、裁判失败 | 明确失败或不完整，不回退未知模型；保留可用部分结果；整任务时限覆盖案例和裁判预算；无自动重跑导致重复调用 |
| AC-25 | 浏览四个页面并走上传→复用案例→评测→报告 | 导航恰为约定四类；Worker 与模型配置集中；评测集管理独立保留；无财务、回放、组织角色、多模式等残余主流程 |
| AC-26 | 初始化管理员、登录登出、修改密码、未登录写入及 CSRF 请求 | 单管理员可正常使用；无需二次输密码；未授权请求/CSRF 拒绝；不能重复抢占初始化；本机默认与远程显式暴露符合方案 |
| AC-27 | Linux x86_64 全新环境从发布候选 Compose 启动 | 除 Docker/网络及用户模型登录外不要求企业账号或额外服务；自动建库和内置 Worker 接入；完成一条真实 Codex 评测；记录真实耗时与手动步骤 |
| AC-28 | macOS arm64 Docker Desktop 整套启动；两种支持平台独立 Worker 接入 | 对应架构产物可用；均能真实运行；本机 Worker 不被强制要求安装中心/数据库；不静默修改已有 Codex；不声称 Windows 原生已支持 |
| AC-29 | 无模型凭据、端口冲突、Worker 离线、中心地址不可达 | 有明确诊断与下一步；示例浏览/文件管理可用；真实执行前置条件缺失不会假成功；不终止用户其他进程；不输出授权码到普通日志 |
| AC-30 | 上传资源和完成任务后重启；备份并恢复到全新环境 | 资源、启用版本、报告、会话相关配置按设计保持；PG/文件/密钥完整恢复；文件摘要一致；启动或迁移不覆盖已有数据 |
| AC-31 | 发布候选执行来源、依赖、许可证、秘密与质量审计 | 必要授权已明确；第三方许可完整；UGLIC 与 skill-release-audit 完成；非误报问题修复并复核；误报有依据，不能靠禁用检查通过 |
| AC-32 | 从最终公开版本与镜像按 README 重做最短安装路径 | 文档命令真实有效，版本/摘要一致；合成示例可复现；最终仓库、CI、版本及产物可查；无开发机残留前提；所有必需项有证据 |

## 3. 最短真实 E2E

### E2E-A：没有案例 → 生成 → 维护 → 全量评测

1. 从干净部署初始化管理员与可用 Worker，配置真实 Codex 连接。
2. 上传合成 Skill，确认无对应案例；点击取消，验证没有生成调用。
3. 再次点击并确认生成；检查候选案例进入草稿，Skill 文件不变。
4. 修改其中一个断言，增加一个边界案例，校验、保存并启用。
5. 点击标准评测；核对冻结清单与启用版本全部案例一致。
6. 等待真实执行与单裁判完成；核对原始报告和网页结论一致。
7. 再次发起评测，确认直接复用案例，没有生成任务。

### E2E-B：独立 Worker 单码接入

1. 中心运行，停止内置 Worker；独立机器只准备 Worker 运行前提和可用 Codex。
2. 中心生成一个含可达地址的授权码，本机输入该码并启动。
3. 自动上线并领取一条全量评测，结果回传中心。
4. 重启本机 Worker，无需再次输入码；原码不能重复兑换。
5. 撤销 Worker，验证不能领取后续任务；页面明确提示等待可用 Worker。

### E2E-C：历史可追溯与故障

1. 运行评测过程中编辑并启用案例新版本，确认当前任务仍使用旧版本。
2. 制造断连超过租约，确认没有自动重复执行。
3. 用户手动重试，确认新 attempt 与旧失败分别保留。
4. 提交迟到旧回执，确认不能覆盖新状态；取消新任务，确认进程退出。
5. 重启中心并恢复备份，历史版本和报告仍可读取且摘要匹配。

## 4. 证据和放行规则

开发时将脱敏验收记录保存到 `docs/verification/<release>/`，每条记录至少包含：验收 ID、提交 SHA、镜像/二进制版本、OS/架构、时间、前置条件、实际结果、原始产物摘要及证据相对路径。

真实调用原始记录保存在私有测试产物区，公开证据只包含合成数据和脱敏摘要。屏幕截图不能单独证明后端执行完成，源码单测也不能替代浏览器和真实 Worker 验收。

发布阻断条件：任意必需项 FAIL/BLOCKED/NOT_RUN；凭据泄露；越权写入；案例被静默丢弃；未执行被标通过；输入/历史结果被覆盖；失联造成重复执行；全新环境无法复现；来源授权或必要审计未解决。

小型视觉问题可记录后续修复，但不得把核心可用性、数据完整性或范围缺失降为视觉问题。默认参数改变后复核相关验收；不因所有检查曾在旧提交通过就放行新的未测候选。
