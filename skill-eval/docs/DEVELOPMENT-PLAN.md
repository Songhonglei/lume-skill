# 开发计划

日期：2026-10-23。状态：开发中；逐项状态和证据见 [实现进度](IMPLEMENTATION-STATUS.md)，阶段尚未整体验收。

范围依据：[完整方案](PRODUCT-AND-TECHNICAL-PLAN.md)。验收依据：[验收标准](ACCEPTANCE-CRITERIA.md)。先验证最高风险的真实 Codex 链路，再迁移管理功能。

## 1. 阶段与依赖

```text
P0 范围及干净仓库
  → P1 skill-up 0.14.0 + Codex 可执行闭环
  → P2 本地 Skill / 评测集及版本
  → P3 独立 Worker 与可靠任务协议
  → P4 管理页面与案例生成闭环
  → P5 一键部署与首次引导
  → P6 集成验收与开源发布
```

P1 使用最小本地 harness 验证技术，不抢先构建整套管理页面。P2 期间可定义 P3 接口，但文档不要求并行代理或多仓库开发。

## 2. 工作包

### P0：范围与干净仓库

- D00：在当前目录初始化新的 Git 仓库和忽略规则；保留本轮方案文档，不引入原项目历史。
- D01：梳理来源白名单、通用模块、需要重写的边界及第三方许可；不读取或复制无关私有数据。
- D02：建立 frontend/backend/worker/examples/deploy 骨架，固定工具链与锁文件；列出 Python、Node、Codex 及操作系统要求。
- D03：准备完全合成的 Skill 与案例种子：正常能力、可控错误、输入边界、技术失败。不得将真实业务资料换名后充当合成数据。

交付：可审阅的来源清单、干净目录、依赖清单、测试素材。退出条件：AC-01、AC-02 的静态范围检查通过；确认后续公开来源可处理。

### P1：先跑通 0.14.0 与 Codex

- D10：固定 skill-up 0.14.0 的下载来源、平台文件与校验摘要，替换旧 0.10.0 前提。
- D11：验证原生 Codex adapter 的确切 CLI 版本、登录方式与模型连接；分别在宿主机和内置 Worker 容器验证。只读取用户明确选择的配置，不升级系统 Codex。
- D12：用真实命令验证 validate、list-cases、run、event-log、result.json 和 HTML；确认 expect、script、agent judge 的结果与退出码关系。
- D13：通过 Codex 和固定的 skill-upper 指令生成候选案例；确认只生成案例、不修改 Skill、不自动开始评测。
- D14：建立统一结果映射：执行状态与结论分离；记录原始文件、冻结案例数、跳过和错误。
- D15：测试无效登录、错误模型、失败断言和超时；保证不会静默切模型、关闭沙箱或把空报告标为通过。

交付：兼容矩阵、真实成功和失败样例、生成样例、薄适配层。退出条件：AC-03、AC-04、AC-15、AC-16、AC-24 的核心执行验证通过；内置容器方案可实际运行。失败时先解决适配，不以假报告推进。

## 3. 测试策略

- 数据版本、任务竞争、鉴权与持久化使用隔离 PostgreSQL 验证，不能用 SQLite 假装覆盖 PG 行为。
- CLI 适配使用真实 0.14.0 样例，并至少完成 Codex 生成、规则判分、脚本判分和语义裁判的真实调用；结构测试不能替代实际模型链路。
- 故障测试覆盖无效登录、摘要不匹配、取消、断连、重复提交和中断后重试。
- 浏览器测试只覆盖关键用户路径及编辑保真；无需为每个低风险样式修改建立测试。
- 自动生成质量用已知正确/错误 Skill 变体校验：同一冻结案例至少能识别一个预设行为缺陷，不能只检查“生成了文件”。
- 通过后只复测受后续改动影响的检查，不反复执行无变化的耗费模型调用。

## 4. 范围控制与停止条件

以下实现选择已可直接推进：保留 PG、本地文件库、轮询领取、单管理员、单并发、受控版本、简单能力匹配。不要重新询问是否使用企业调度或回放。

出现下列情况时先反馈具体影响与可选方案，再改变设计：

- 0.14.0 的原生 Codex adapter 无法满足真实执行，必须更换引擎、重写大型适配层或降低隔离。
- 一键部署必须要求用户额外搭建外部服务，或需要高权限宿主机挂载。
- 核心源码不能取得公开许可，需要大范围重写。
- 新要求涉及多租户、自动修复、采集回放或跨 Skill 共享。

不先建设插件市场、复杂调度、通用权限平台、可视化工作流编排和跨版本分析。确有必要时提交具体收益与成本再确认。

## 5. 进度记录格式

实现时维护任务 ID、状态、对应提交、验收 ID 和证据路径；初始全部为 TODO。阶段完成以退出条件为准，不以代码量或页面出现为准。

每阶段只交付与当前目标相称的证据。日历工期在 P1 完成兼容性验证后估算，当前不将尚未实测的 Codex/容器适配工作包装成确定工期。
